# 设计：全板块两级选股 + 大盘局势研判

- 日期：2026-07-13
- 状态：✅ 已实现并本地实测通过（feat/all-sector-screening 分支，未提交）
- 影响文件：`universe.py`（重写）、`datasources.py`（+大盘源）、`llm.py`（+大盘研判/增强选股）、`app.py`（+大盘接口/加宽选股）、`templates/index.html`、`static/app.js`

## 1. 目标

1. 市场选股的「侧重板块」从**仅科技**扩到**全市场所有板块**，并支持下钻到**二级细分**。
2. 每次选股/板块分析**结合大盘局势**：AI 先拿到大盘研判结论，再据此选股。
3. AI 输出更**严谨理性**：提示词更详细、温度降到 0.15、强制只依据给定数据。

非目标（YAGNI，本次不做）：
- 动态抓取板块成分（东财/通达信全量成分）——列为未来可选，v1 用精选骨架。
- 北向资金 / 行业轮动排名——本次大盘取 balance 档，不做。
- 港美股、可转债、ETF 选股。

### Helper 重写（保持向后兼容命名）
- `all_codes() -> list[str]`：全池去重保序。
- `primary_sectors() -> list[str]`：全部一级名。
- `sub_sectors(primary: str) -> list[str]`：某一级下的二级名。
- `codes_of(focus: str) -> list[str]`：focus 为一级名→该一级全部；为二级名→该二级；为 `""`→全池。
- `sector_of(code: str) -> tuple[str, str]`：代码→(一级, 二级)，找不到返回 `("其他","其他")`。
- `taxonomy() -> dict[str, list[str]]`：`{一级: [二级...]}`，供前端下拉与 `/api/config`。

> **破坏性变更**：`sector_of` 返回类型由 `str` 改为 `tuple`。调用点在 `app.py:_screen_rows`（290、301 行）与 `llm.market_screen` 的行数据，需同步改。旧的 `sectors()` 语义变为 `primary_sectors()`，保留 `sectors()` 作别名以防遗漏调用。

## 3. 大盘数据源：`datasources.py` 新增

### `index_quotes() -> list[dict]`
- 源：腾讯 `qt.gtimg.cn`（GBK，不封 IP，复用现有 `_http_get`）。
- 指数：上证 `sh000001` / 深成 `sz399001` / 创业板 `sz399006` / 沪深300 `sh000300` / 科创50 `sh000688`。
- 每项返回 `{code, name, point, chg_pct, amount_yi}`（点位、涨跌%、成交额亿）。
- 指数行的字段布局与个股略不同，需单独解析（实现时用 a-stock-data skill 校准字段下标）。

### `market_breadth() -> dict | None`
- 源：东财，走 `em_get()` 限流。取 涨家数 / 跌家数 / 涨停数 / 跌停数 / 两市成交额。
- **失败或被封→返回 `None`，绝不阻断**（大盘研判在缺情绪数据时降级为「仅指数」）。

## 4. AI 层：`llm.py`

### 全局：温度 0.15 + 更强 system 提示
- `_chat` 默认 `temperature` 由 0.3 → **0.15**，所有分析型调用（daily / position / screen / overview）统一继承，不再逐个覆盖。
- `_DISCLAIMER` 强化：只依据给定客观数据、不得编造未提供数字、只描述波动幅度不预测方向、所有结论标注「参考信号，不构成投资建议」。

### 新增 `market_overview(indices, breadth, web_context="") -> dict`
提示词：给出各大指数涨跌 + 成交额 + 情绪（涨跌家数/涨停数，可能为空），要求判定大盘状态并**指导选股攻防**。max_tokens=6000，temperature=0.15。

返回 JSON：
```json
{
  "regime": "强势|中性偏多|中性|中性偏空|弱势|避险",
  "style": "大盘价值|小盘成长|均衡|防御",
  "sentiment": "赚钱效应一句话（结合涨跌家数/涨停）",
  "risk": "当前大盘最大风险点",
  "guidance": "对选股的指导：该进攻/均衡/防守，仓位建议",
  "one_liner": "一句话大盘研判（顶部条展示）"
}
```

### 增强 `market_screen(rows, capital, focus_sector="", market_ctx=None, web_context="") -> dict`
- 新增入参 `market_ctx`（`market_overview` 的返回）。
- 提示词结构：①先陈述大盘 regime/style/guidance；②要求**结合当前大盘状态选股**（弱市重防守低估值、强市可进攻高弹性）；③逐项定义指标含义与打分维度；④要求覆盖多个二级板块、每只标注一级/二级；⑤强制不编造数字。
- `focus_sector` 可为一级或二级名；提示词据此侧重。
- 温度 0.15，max_tokens 保持 9000。
- 返回增强：
```json
{
  "overall": "结合大盘的整体研判一句话",
  "market_regime": "回显采用的大盘状态",
  "picks": [{"code":"","name":"","primary":"","sub":"","action":"buy|watch",
             "confidence":"high|mid|low","lot_cost":0,"reason":"","risk":""}],
  "budget_plan": "资金配置建议",
  "sector_view": "按二级板块点评强弱"
}
```

## 5. 后端接口：`app.py`

### 新增 `GET /api/market/overview`
- 取 `index_quotes()` + `market_breadth()` + `llm.market_overview()`；缓存数分钟（模块级时间戳缓存，避免频繁触发慢 AI 与东财限流）。
- 无 key 时仍返回指数原始数据（`ai=None`），前端只显示指数条。
- 返回 `{ok, indices, breadth, ai, cached, updated}`。

### 改 `POST /api/recommend/screen`
- `focus` 支持一级/二级；调 `market_screen` 前先取（缓存的）大盘 ctx 注入。
- `_screen_rows(capital, focus)` 采样策略：
  - focus=二级 → 只取该二级的 `codes_of`；
  - focus=一级 → 该一级下各二级均衡采样；
  - focus="" 全市场 → 跨一级均衡采样，**总量 cap 由 28 抬到 36**（控 token/时延；每只成本 = 1 次腾讯批量 + 1 次新浪 metrics）。
- 行数据 `sector` 字段改为 `primary/sub` 两列。

## 6. 前端：`templates/index.html` + `static/app.js`

### 大盘研判条（常驻顶部）
- 顶部新增一行：五大指数涨跌（红涨绿跌）+ AI `one_liner`，点击展开看 regime/style/sentiment/risk/guidance。
- 启动与每次自动刷新时拉 `/api/market/overview`；**独立单调计数器 `mktSeq`** 防错位（遵循项目异步令牌约定）。
- 指数条即使 AI 未配置也显示（纯行情）。

### 板块下拉两级化
- `scr_focus` 单个 `<select>` 用 `<optgroup label="一级板块">`：一级作分组标题，二级作选项；每个一级也提供「整个X板块」可选项；保留「不限（全市场）」。
- 扩展 `/api/config` 增加 `taxonomy` 字段，前端据此动态渲染分组下拉，避免硬编码板块名。
- 文案「从 44 只科技股」→「从全市场 N 只候选跨板块筛选」。
- 选股结果卡片展示 `primary/sub` 两级标签。

## 7. 配色/约定（沿用）
- 红涨绿跌；情景区间只描述波动不预测方向；所有 AI 输出标注参考信号。
- 不加载外部字体/图表；异步渲染带请求令牌（新增 `mktSeq`）。

## 9. 风险 / 限制
- 东财 `market_breadth` 可能间歇封锁 → 已设计降级不阻断。
- 全市场精选池需人工维护、覆盖有限（非全量）；`name` 仅兜底。
- 指数字段下标需按腾讯实际返回校准（实现时用 a-stock-data 核对）。
- 两处破坏性变更：`sector_of` 返回 tuple、`_screen_rows` 行结构 primary/sub——需同步改所有调用点，避免 KeyError。
- 全市场 36 只候选会增加 screen 时延（新浪 metrics 并发 8 线程，约 +几秒）。
