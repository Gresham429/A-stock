# 设计：多档本地投资画像 + 总资产分级玩法 template

> 日期：2026-07-14 ｜ 状态：待用户 review ｜ 类型：功能（新 profile_store + 分级引擎 + template + 全 AI 注入 + UI）

## 目标（用户定）

- 本金从「写死 1 万」→ **可配数值**，**允许本地多人/多档建档**，随时切换。
- 分级依据 = **总资产 = 现金本金 + 已持有股票市值**（不是只看现金）。
- 系统**动态**据总资产落到某档 → 该档一套**玩法 template**（不同资产不同打法）→ 注入所有 AI 分析，做「全方位博弈」。
- 核心：**期望为正**——小资产搏赔率、大资产求稳，但都要「胜率×赔率 > 1」。

## 一、分级分类（我按仓位管理/流动性/冲击成本理论设计，5 档）

按**总资产**（现金 + 持仓市值）自动落档：

| 档 | 总资产 | 核心逻辑 |
|----|--------|----------|
| **微型** | < 3 万 | 1 手成本约束强、买不起几只 → 极致集中、搏赔率 |
| **小型** | 3–30 万 | 灵活、可短线/打板 → 集中+成长题材 |
| **中型** | 30–200 万 | 开始要分散、兼顾流动性 → 均衡 |
| **大型** | 200–2000 万 | 冲击成本显现、回撤要控 → 分散+白马 |
| **超大** | ≥ 2000 万 | 机构化、进出影响价格 → 严格分散+大盘蓝筹 |

每档一套结构化 template（可编辑），维度：

| 维度 | 微型<3万 | 小型3–30万 | 中型30–200万 | 大型200–2000万 | 超大≥2000万 |
|------|---------|-----------|-------------|---------------|------------|
| 持仓只数 | 1–2 | 2–4 | 4–8 | 8–15 | 15–30 |
| 单标的仓位上限 | ≤70% | ≤40% | ≤25% | ≤15% | ≤8% |
| 标的池 | 中低价/题材弹性 | 成长+题材 | 成长+价值+题材 | 白马+行业龙头 | 大盘蓝筹/流动性好 |
| 周期偏好 | 波段/短线 | 波段(可短线) | 波段+趋势 | 趋势/波段 | 长线/趋势 |
| 可用打法 | 事件/题材/波段 | +打板(严控) | 趋势+价值 | 趋势+配置 | 配置+仓位管理 |
| 换手/成本 | 灵活但算成本 | 中频 | 低频 | 低频、分批 | 极低频、大额分批算冲击 |
| 单笔风险 | ≤2% | ≤1.5% | ≤1% | ≤1% | ≤0.5% |
| 现金管理 | 留 1 手子弹 | 留 20–30% | 留 20% | 动态 20–40% | 战略现金仓 |
| 正期望锚 | **搏高赔率**、快进快出、错就砍 | 赔率优先、顺势 | 胜率赔率并重 | **求稳**、控回撤 | **绝对低回撤**、资产保全优先 |

> 阈值/维度**可编辑**（存 DB），用户不认同随时改；上表是我给的合理初值。

## 二、多档本地建档（profile_store）

- 新 `profile_store.py`（SQLite `data/profiles.db`，gitignore），仿 `paper_store` 多存档：
  - profile：`{id, name, cash(现金本金), risk_pref(可选:稳健/均衡/激进), created_at, is_active}`。
  - 一个 `active` profile 全局生效；`GET/POST/DELETE /api/profiles`、`POST /api/profiles/active/<id>`。
- **持仓归属**（一个要你拍板的点，见文末）：v1 用**全局 portfolio**（你的真实持仓），profile 只带现金本金；总资产 = active.cash + 全局持仓市值。（若要"每档独立持仓"另说，见开放问题。）

## 三、动态分级引擎

- `tiers.py`（或并入 profile_store）：`total_assets = active.cash + Σ portfolio.with_pnl 市值`；`tier_of(total)` 按阈值落档；`template_of(tier)` 取该档 template（DB，可编辑）。
- 自动同步现有 `rules_store` 的 scenario 本金维（微/小→小、中→中、大/超大→大），复用规则场景过滤。

## 四、注入所有 AI（全方位博弈）

- 拼一个【本金玩法档】块（当前档 + 总资产 + 该档 template 关键项 + 正期望锚）注入 `daily_recommendation` / `market_screen` / `position_advice` / `entry_advice` / `market_overview`。
- entry 的 `capital` 改用 active.cash（取代写死 1 万）；screen 的资金默认填 active.cash。
- AI 据「总资产 + 持仓构成 + 本档打法」给**组合级**建议（该加/该减/该分散/单标的仓位是否超限）。

## 五、UI

- 顶部/设置区加**画像切换器**：下拉选 active profile + 显示「总资产 X 元 · 当前档：中型 · 玩法：均衡分散」+ 新建/改本金/删档。
- AI 面板显示当前档 + 一句话玩法（复用溯源条风格）。
- 「档位 template」可在类似规则 modal 里查看/编辑。

## 涉及文件
| 文件 | 改动 |
|------|------|
| `profile_store.py`（新） | 多档建档 + active + 总资产/档位/template |
| `app.py` | /api/profiles* 路由；各 AI 路由注入档位块、capital 用 active.cash |

## 测试 / 风险
- 总资产计算随持仓实时市值波动 → 档位可能在边界跳动：加**滞回**（跨档需超阈值 ±10% 才切，避免抖动）。
- 多档切换要带请求令牌，避免旧档结果覆盖。
- profile 空/无持仓 → 总资产=现金，正常落档。

## 决定（已定）
**持仓归属 = B · 每档独立**（用户 2026-07-14 从 A 改为 B）：每个画像各记各的持仓，互不干扰。`portfolio.py` 按 active 画像隔离存储（`portfolio.json` = `{"by_profile": {pid: [holdings]}}`，旧格式自动迁移到当前画像）；总资产 = active.cash + **该画像自己的**持仓市值。切换画像 → 持仓面板/总资产/档位/AI 分析全部按该画像走。

## v1 范围收敛（避免过度）
- **template 定义**：v1 用代码常量 `TEMPLATES`（5 档玩法，见上表），**只读展示 + 注入**；用户可编辑的是**profile 的现金本金**（灵活变更的核心诉求）。模板文案的 UI 编辑列为后续。
- **注入方式**：`_tier_block(...)` 文本块**前置到各 AI 的 `web_context`**（5 个函数都收 web_context），**零 llm 签名改动**。
- **rules 场景同步**：切换 active profile 时，按档自动 `set_scenario` 的本金维（微/小→小、中→中、大/超大→大），周期维保留用户选择。
