# 全市场股票池 + 板块日变化统计（design）

> 2026-07-15。把 `universe.py` 手工维护的 170 只龙头池，换成全 A 动态池（5527 只）+ 全板块归属 + 板块日变化历史；
> 选股改为「先定板块 → 板块内按需算形态」。

## 目标

用户原话：「把池子本身做的很大，但是推荐选股的时候依赖关注的板块，同时我们需要统计比较不同的板块每日变化；
所以你的板块要全，池子要全，但是最后的选择和量相当于有缓存」。

拆成三件事：

1. **池子要全** — 全 A 5527 只动态名单，自动更新，不再手工维护。
2. **板块要全** — 每只股都有板块归属（申万一级 + 细分 + 概念），覆盖率 ~100%。
3. **板块每日变化可比较** — 板块级日涨跌/家数/领涨股落盘成历史，可跨日对比。
4. **选股依赖关注板块 + 缓存** — 不对全市场算形态，只对关注板块内的股票算，结果进缓存。

## 关键洞察：不建全市场日K仓库

最初设想「全市场技术形态初筛」需要 4700 只的日K仓库（回填 + 每日增量 + 前复权追溯校准），
这是整个方案里最脏最易错的部分。

用户的「选股依赖关注板块」直接消掉了它：**形态只需在关注板块内算**，一个板块 ~100 只，
新浪 `getKLineData` × 100、8 线程并发 ≈ 3s，按需拉 + 当日缓存即可。

代价：首次点某板块等 ~3s。收益：省掉一整个子系统，且没有复权校准的正确性风险。

## 数据源实测（2026-07-15，本机 IP）

| 需求 | 源 | 结论 |
|------|-----|------|
| 全A名单 | 新浪 `Market_Center.getHQNodeData?node=hs_a` | ✅ **5527 只**，80/页 × 70 页，0.8s/页，可并发 → 全量 ~10s |
| 名单总数 | 新浪 `getHQNodeStockCount?node=hs_a` | ✅ 返回 `"5527"` |
| 行业分类 | 新浪 `newSinaHy.php` | ❌ 仅 49 类、覆盖 3013/5527（**54%**），表老旧，弃用 |
| 行业分类 | 东财 `push2/api/qt/clist/get`（一次拿全市场+行业） | ❌ **本机 IP 被封**（`RemoteDisconnected`），带/不带代理、走/不走 `em_get()` 均失败 |
| 行业分类 | 东财 `push2/api/qt/**slist**/get`（逐股反查所属板块） | ✅ 0.2s/股，**同域名不同端点，未被封** |
| 实时行情 | 腾讯 `qt.gtimg.cn` | ✅ 但单 URL 装不下 5400 → 必须分批 |
| 日K | 新浪 `getKLineData` | ⚠️ 一股一请求，仅按需用 |

**东财是按端点封的**：`clist`（批量出数口）封，`slist`（逐股）放行。这决定了行业归属只能逐股回填。

## 板块解析规则（已验证 12/12）

`slist` 返回混合标签，例：

```
600760 → ['航空装备Ⅲ','航空装备Ⅱ','国防军工','山东板块','航天航空','军工','HS300_',...]
300750 → ['电池','锂电池','电力设备','福建板块','新能源车','富时罗素',...]
688981 → ['集成电路制造','电子','半导体','AH股','融资融券','上证50_',...]
```

**标签顺序不稳定**（600760 是三级→二级→一级；300750/688981 顺序各异），`Ⅱ/Ⅲ` 后缀也只有部分股票带。
因此不能靠顺序或后缀解析。规则：

- **一级** = 硬编码申万一级 31 类锚点匹配（稳定、小、公开）→ 实测 12/12 命中。
- **细分** = 前 4 个标签里第一个「非一级 / 非地域（结尾『板块』）/ 非指数（结尾『_』）」，去掉 `Ⅱ/Ⅲ` 后缀。
- **概念/地域/指数** = 其余标签，按后缀分类存入 `stock_sectors.kind`。

细分**不严格等于申万二级**（688981 得到「集成电路制造」而申万二级是「半导体」），但语义正确、自解释，
作为细分方向标签完全够用。文档与 UI 用「细分」而非「申万二级」措辞，避免误导。

验证结果：

```
中航沈飞→国防军工/航空装备   宁德时代→电力设备/电池      中芯国际→电子/集成电路制造
紫金矿业→有色金属/铜         比亚迪→汽车/电动乘用车      贵州茅台→食品饮料/白酒
工商银行→银行/国有大型银行   招商银行→银行/股份制银行    汇川技术→机械设备/工控设备
海康威视→计算机/计算机设备   金山办公→计算机/横向通用软件 五粮液→食品饮料/白酒
```

## 架构

```
┌─ 数据层（全，每日/每月刷新）──────────────────────────────┐
│  universe_store.py  →  data/universe.db                   │
│  ├ stocks         5527 只（新浪 hs_a，70 页并发 ~10s，每日）│
│  └ stock_sectors  多对多板块归属（东财 slist 逐股，月度）   │
└───────────────────────────────────────────────────────────┘
                          ↓ 每日收盘后一次
┌─ 统计层（全市场，落盘成历史）─────────────────────────────┐
│  腾讯批量行情 5527 只（60/批 × 78 批，并发 ≈3s）           │
│         ↓ 按板块聚合                                       │
│  sector_daily(date, 板块, 平均涨跌, 涨/跌家数, 涨停数,      │
│               成交额, 领涨股)  ← 「板块每日变化对比」数据源 │
└───────────────────────────────────────────────────────────┘
                          ↓ 选股时才走
┌─ 选股层（窄，按需，带缓存）───────────────────────────────┐
│  关注板块（用户选 / 由 sector_daily 挑强势板块）           │
│         ↓ 板块成分股 ~100 只                               │
│  按需拉日K（新浪 × 100，8 线程 ≈3s）→ data/kline.db 缓存   │
│         ↓ PA 形态初筛（区间位置/波动率/均线）              │
│  几十只 → AI                                               │
└───────────────────────────────────────────────────────────┘
```

## 三个折中（已与用户确认）

**1. 板块归属多对多，但额外存「主行业」保住旧契约。**
一只股同时属于「航空装备/国防军工/航天航空/商业航天概念」，A 股本来如此。但现有
`sector_of(code) → (一级, 二级)` 是单归属契约，`news_store.py:169,183` 与 `app.py:875,888,917,960` 都依赖它。
处理：`stocks` 表存 `sw1`/`sub` 两列作主行业 → `sector_of` 签名与语义不变、旧代码零改动；
概念板块作为附加维度，只给板块统计与选股用。

**2. 手工的 10×48 `MARKET_UNIVERSE` 不删，降级为「精选龙头」标记。**
它是已沉淀的判断，且回填失败时是降级路径。保留为 `is_leader` 标记 + 一个特殊板块「精选龙头」。

**3. 次新股过滤放在选股层，不在名单层。**
新浪 hs_a 不返回上市日期。但形态初筛本就需要 ≥60 根日K，不够的自然出局——次新过滤是免费副作用。
板块统计则应包含次新（它们是真实成分股）。

## 排除规则（`stocks.eligible`）

| 规则 | 判定 | 成本 |
|------|------|------|
| ST / *ST / 退市整理 | `name` 含 `ST` | 零成本（名单自带） |
| 北交所 | `code` 以 `4`/`8`/`920` 开头 | 零成本 ⚠️ **920xxx 是新号段**，新浪返回里已有 `bj920000` |
| 停牌 / 无报价 | 新浪 `trade == 0` 或腾讯无返回 | 零成本 |
| 次新（<60 根日K） | 选股层日K不足时自然出局 | 免费 |

`eligible = not ST and not 北交所 and not 停牌`。板块统计用全量，选股用 `eligible`。

## 表结构 `data/universe.db`

```sql
CREATE TABLE stocks (
  code TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  board TEXT,                    -- sh/sz/cyb/kcb/bj
  sw1  TEXT DEFAULT '',          -- 主行业·申万一级（sector_of 的 primary）
  sub  TEXT DEFAULT '',          -- 主行业·细分（sector_of 的 sub）
  is_st INTEGER DEFAULT 0,
  is_suspended INTEGER DEFAULT 0,
  is_leader INTEGER DEFAULT 0,   -- 命中手工精选池
  eligible INTEGER DEFAULT 1,
  sectors_at TEXT DEFAULT '',    -- 板块归属回填时间，空=未回填
  updated_at TEXT
);
CREATE TABLE stock_sectors (
  code TEXT NOT NULL,
  sector TEXT NOT NULL,
  kind TEXT NOT NULL,            -- sw1 | sub | concept | region | index
  PRIMARY KEY (code, sector)
);
CREATE INDEX idx_ss_sector ON stock_sectors(sector);
CREATE TABLE sector_daily (
  date TEXT NOT NULL, sector TEXT NOT NULL, kind TEXT,
  n INTEGER, avg_chg REAL, up_n INTEGER, down_n INTEGER, limit_up_n INTEGER,
  amount REAL, leader_code TEXT, leader_name TEXT, leader_chg REAL,
  PRIMARY KEY (date, sector)
);
CREATE TABLE meta (k TEXT PRIMARY KEY, v TEXT);
```

`data/universe.db` 与 `data/kline.db` 均 gitignore。

## 刷新节奏

| 数据 | 频率 | 成本 | 触发 |
|------|------|------|------|
| `stocks` 名单 | 每日 | ~10s | launchd 晚间 / 启动时惰性 |
| `stock_sectors` 归属 | 首次回填 + 月度补新股 | **首次 ≈92 分钟**（5527 × `em_get` 限流 ≥1s），之后仅新股 | 后台线程 |
| `sector_daily` | 每交易日收盘后 | ~3s | launchd 20:30 |
| `kline` | 按需 + 当日缓存 | ~3s/板块 | 选股时 |

首次 92 分钟回填走后台线程 + 断点续传（`sectors_at` 为空的才抓），参照 `news_store.backfill()` 既有模式。
回填期间 `sector_of` 降级到手工 `MARKET_UNIVERSE`，功能不中断。

## 降级路径

| 失败 | 降级 |
|------|------|
| 新浪 hs_a 挂 | 用 db 里上次的名单；db 为空 → 手工 `MARKET_UNIVERSE` |
| 东财 slist 挂/被封 | 已回填的照用；未回填的 `sector_of` 落回手工池，再落 `('其他','其他')` |
| 腾讯批量挂 | 当日 `sector_daily` 跳过，不写脏数据 |
| 日K 挂 | 该股不参与形态初筛，不阻断其余 |

- **一期** ✅：`universe_store.py` — 名单 + 板块归属回填 + `sector_of`/`codes_of`/`taxonomy`（保持签名）。

## 实施记录（2026-07-15）

### 与设计的偏差

**板块日统计不走腾讯分批。** 新浪 hs_a 返回自带 `changepercent`/`amount`/`turnoverratio`/`mktcap`/`nmc`/`per`/`pb`，
名单刷新与板块统计共用同一次拉取（~12s），比设计里的「腾讯 78 批」更省。

**日K仓库整个没建，也不需要建。** 形态初筛落在 `ds.sina_metrics`（新浪 MoneyFlow，一份数据出
波动率/区间位置/20日动量/资金流），板块内 ~100 只并发 ~10s，无需日K与复权校准。设计里
"按需拉日K"这步实际被 sina_metrics 取代。

**形态初筛只在「关注板块」路径生效。** 池 ≤ `_PA_RANK_MAX`(200) 时对全部成分股算形态再排序；
全市场路径池太大，退回 `_PRESCREEN`(600) 流通市值预筛 + 均衡采样。

### 扩池暴露的崩溃点（手工龙头池数据干净、永不触发）

| 位置 | 症状 | 修法 |
|------|------|------|
| `ds.tencent_quote` | 全池 4989 只拼成 44KB URL → **HTTP 414**（实测 800 只可过、2000 只失败） | `QUOTE_CHUNK=400` 分批并发，全池 1.7s / 100% 覆盖 |
| `ds._annualized_vol` | 收盘价含 0 → `math.log` **math domain error**，穿透 `executor.map` 打崩整个选股 | 窗口含非正值返回 None |
| `ds.sina_metrics` | `closes[-21]==0` → `ZeroDivisionError`；`float(x['trade'])` 在 try 块外，空字段 `ValueError` 穿透 | 两处设防 |
| `app._safe_metrics` | — | 兜底包装，单只异常不拖垮整批 |

### 解析规则的坑

东财 slist 同一板块会以 `银行Ⅱ` 与 `银行` 两种形态返回。若按**原始标签**分类却按**去后缀名字**去重，
`银行Ⅱ` 会被判成 concept 并抢占去重位，真正的 `sw1` 标记永久丢失。表现隐蔽——`codes_of('银行')`
照常能用（不筛 kind），只有 `sector_ranking(kind='sw1')` 静默漏板块。已改为去后缀后分类 + sw1/sub 判定优先，
固化为 `tests/test_universe_store.py` 回归用例。

### 跨进程互斥

`ds.em_get` 的限流器是进程内全局（`_em_last_call`），app 与命令行同时回填会让东财实际请求速率翻倍。
东财已因此封掉 clist；slist 再被封则功能全废。故加 db 心跳锁（`meta.backfill_hb = pid,ts`，
超 120s 视为进程已死可抢占），与既有 `threading.Lock` 双重互斥。

### `_pa_score` 权重说明

四项各 25 分，权重是**启发式先验、非回测得出**，按「波段 + 波动型」取向设定：
可分析性（`vol=None` 出局，次新/停牌在此自然剔除）、波动（年化 30–90% 满分）、
资金（主力 20 日净流入为正，按额饱和）、动量（20 日涨幅 0–30% 满分）、位置（区间位置 30–70 满分，避免追顶接刀）。
它只是**粗筛**——决定谁占用送进 AI 的 36 个名额；真正 PA 判断仍由 AI 依 `rules_store` 84 条规则做。

## 不做（YAGNI）

- 全市场日K仓库与前复权校准 —— 被「按板块按需」消解。
- 申万二级严格对齐 —— 细分标签语义已够用，强对齐需额外维护 134 类名单。
- 美股/港股/ETF —— 超出「大A」范围。
