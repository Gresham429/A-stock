# 踩坑备忘 / Pitfalls

> 每条都是**真的踩过并付出代价**的。改相关代码前必读。
> 按「会不会让你写出错的东西」排序，不按时间。

## 一、会让结论变假的（最危险）

这类坑不报错、不崩溃，只是**让你相信一个错的结论**。

### 0. 注入的规则与注入的数据必须对得上

2026-07-16 早盘：12 个 agent **11 个产出 0 意向**，且非风控否决（`否决 0`）。
`skip_reason` 清一色「数据不足：缺少K线、趋势、均线、信号棒」。

**AI 是对的**——规则库注入 84 条价格行为规则（**37 条**要 K线/均线/趋势/信号棒），
提示词却只给静态标量（形态分/波动/区间位置/20日涨），还写着「严格遵循【交易分析框架规则】」。
它只能援引 **R6「看不懂就等」**——**在正确地服从规则**。
且【今日大盘】传的是 `sector_ranking()[0]["sector"]`，AI 看到的「大盘」字面上就是「传媒」两个字。

代价：每天 12 agent × 48s v4-pro 全烧掉换回「数据不足」，**教训库结构上永远是空的**
——直接卡死「让 agent 跑起来攒数据」这个第一优先级。**且没有任何报错**。

这与 #2（教训与因子矛盾）同类：**系统内部两个部分互相矛盾，而矛盾不会自己喊出来**。
上线新规则/新教训/新提示词块时，先问：**它要的数据，我给了吗？**

### 0a. 判「失败」必须看结果，且地平线要够长 —— 5 日判罪 **33.1% 判反**

教训库 9 类里**只有 `below_breakeven` 一类真的看了结果**。
`chase_high` 的文案写着「>85 视为追高，**此后回落**」，但 `detect_failures` 在成交的
**同一个循环**里就记（传 `settled["filled"]`）——那时「此后」还没发生，
**全仓 grep 过：`add_lesson` 只有 2 个调用点，无任何事后结算**。
它在向 5 个 AI 陈述**从未被验证的结果**。

且系统横向矛盾：`factor_lab.HORIZONS=(5,10,20)`，选股方向按未来 5–20 日收益验证，
教训却在 T+0 判罪。**选的时候看 20 天，判的时候看 0 天。**

**实测代价**（6240 个真实建仓点，120 只 × 每 5 根一取，超额 vs 上证）：

| 5 日 vs 20 日判罪 | 占比 |
|---|---|
| 结论一致 | 66.9% |
| 5 日判「失败」→ 20 日其实跑赢 | **14.1%**（冤枉） |
| 5 日判「成功」→ 20 日其实跑输 | **19.0%**（放过） |
| **合计判反** | **33.1%** |（相关系数仅 0.452）

**短地平线不是「不够精确」，是系统性地把三成结论判反**，且错标签会注入 5 个 AI。

**两个连带铁律**：
- **必须扣 beta（用超额）**：大盘跌的月份所有买入都亏 → 全记教训 → AI 学到「别买」
  而非「别这样买」。那不是 AI 的错。（同 #5 的 beta 污染红线。）
- **n 不够 → 教训只能是归因，不能是统计**：20–30 笔/年，统计验证要 784 笔（#5）。
  故文案必须是**个案口吻 + 带 n**。「>85 视为追高」是普适规则口吻而证据只有 n=1
  ——**拿单个样本冒充规律，是 #1「拍脑袋定阈值」的翻版**。

`agent_store` 的 docstring 那句「失败归因不需要样本量——它是核对事实」对
`below_breakeven` 成立（卖出即结果，倒贴是事实），但被**过度外推**到了 `chase_high`：
「range_pos=92」是**入场位置**的事实，「这是个错误」是假设。两者被那句话粘在了一起。

### 0b. 盘中日K的最后一根是**昨天**，而「现价」是今天

新浪日K当日 bar 收盘后才有。实测 07-16 12:35 午休：工商银行日K末根=07-15 收 7.51
(=昨收)，而实时价 7.43。喂 AI 时**每根K线必须带日期**——否则它把昨天的 bar 当今日
信号棒读，而价格行为体系读的就是这根。**不报错，只是每次判断都错位一天。**
（日期还能顺带暴露停牌股：日期断档 = 长期没交易。）

### 1. 凡是拍脑袋定的阈值，方向大概率是错的

2026-07-15/16 被数据打脸 **5 次**，无一例外：

| 我拍的 | 数据说 | 证据量 |
|---|---|---|
| `_pa_score` 动量分量：20 日涨幅高 = 好 | **反了**，A股短期反转，IC=-0.056 **t=-8.16** | 162,014 样本 |
| `_pa_score` 波动分量：高波动 = 好 | **反了**（长期），低波动异象 t=-3.43 | 同上 |
| 止损 -8% | -10% 更优（同样压住尾部，触发率 43%→34%） | 108,139 建仓点 |
| `high_vol_entry` 教训阈值 96 | 与 vol 的正向 IC(t=+6.94) **直接矛盾** | 同上 |
| 「因子方向会在 t≈2 抖动，要加迟滞」 | **不会**，505 交易日只翻 1–2 次 | 505 日滚动 |

**结论：能验的参数必须验**（`factor_lab` 那套方法论可复用）；验不了的要**明确标注为纪律参数**（只需用户认可，不假装有数据支持）。

**当前仍未验证的**：`CHASE_HIGH_POS=85`、`STALE_DAYS=20`、`LOSS_CUT_PCT=-12`、`_PRESCREEN=600`。
**明确的纪律参数**（不需验证，但要用户认可）：`MAX_VOL=120`、`MAX_POS_PCT=30`、`MIN_CASH_PCT=10`、`VOL_FLOOR/CEIL=15/130`。

### 2. 教训不得与因子数据矛盾，否则系统在惩罚 AI 服从自己的数据

踩过的完整环路：

```
_pa_score 按 vol 正向 IC 选出高波动股 → AI 听话买入
→ detect_failures 立刻记「波动失控」(阈值 96 是拍的)
→ _lesson_block() 注入 5 个 AI（含用户自己用的 daily/screen/position/entry/market）
→ 下次 AI 避开高波动 → 违背我自己的数据
```

**已修**：有因子回测的属性，教训只在 `direction().sign < 0`（数据判定不利）时才记。
`sign >= 0`（有利**或不显著**）不记——同 `_pa_score`「方向未知不参与打分」原则：**不猜**。

**风险由 `MAX_VOL` 硬门管（风控），教训不重复管、更不该用比风控更严的线**（原 96 < 风控 120，风控放行复盘却判罪，是双标）。

### 3. 补跑/回测必然引入未来函数——除非补的是「既成事实」

**能补的**（不需要重建信息环境）：
- 条件单：`日K low ≤ 止损价` 是既成事实
- 限价挂单：当日走**分时**（只看挂单时刻之后的点）、隔夜走**日K low/high**

**不能补的**：agent 的决策。要在 14:00 重建 10:00 的决策，得重建**整个信息环境**（全市场快照/板块统计/资金流），而 `ds.sina_all_stocks()` **只有当前快照、无 as-of 参数**。任何一处泄漏 = AI 拿 14:00 的答案做 10:00 的题，**结论系统性偏乐观且无法自查**。故时段桶**错过不补**。

**LLM 回测同理不可信**：模型训练时见过 2025 年行情，重放历史决策它会「记得」结果。故量化腿（因子/确定性/大样本/可回测）与 LLM 腿（叙事/判断/小样本/不可回测）**验证方法不同，不能混**。

### 4. 成交价一律取保守值，不取当时更优价

条件单按 `trigger_price`、挂单按 `limit_price` 成交，**不用当日最优**。日K 无日内路径、分时只有每分钟收盘无分钟内高低——乐观假设会**系统性高估策略表现**，这是回测最经典的自欺。**宁可少成交，不可自欺**。

### 5. 样本量的算术（决定什么能验、什么不能）

按用户交易频率（20–30 笔/年）：

| 问题 | 需要 | 折合 |
|---|---|---|
| 「这套策略有正期望吗？」（55% vs 50%） | **784 笔** | **31 年** ← 死局 |
| 「这笔为什么亏？」 | **1 笔** | 立刻 |
| 因子 IC（横截面，每日一个观测） | 600 日 | **已有 162,014 样本** |

**故：放弃统计验证策略优势，转向单笔失败诊断 + 因子回测。**
**红线：绝不让优化器朝收益率进化提示词**——5–8 个样本只会拟合噪音，且标签被大盘 beta 污染（大盘涨时 AI 随便买都赚 → 优化器学到「AI 很棒」→ 你会**相信**它）。

## 二、会让你白干的

### 6. 试跑必须无副作用

`dry_run` 曾也写「复盘」记录 → 幂等门以为今天真跑过 → **开盘后的真跑被自己挡掉**，那天 agent 等于没交易。
**已修**：试跑阶段名带「试跑-」前缀（`_ph()`），幂等靠 `claim_slot()` 原子占位。

### 7. 幂等必须原子，不能靠「查有没有跑过」

`already_ran` 是「开头查、180 秒后才写复盘」——**两个并发 run_all 会双双挤过去**。
实测发生过：10:19:58 与 10:20:08 各起一轮，两轮都跑完(179s/177s)，两个 agent 各跑 2 次。
**已修**：`claims` 表 `PRIMARY KEY (agent_id,date,slot)` 冲突做原子占位；跑失败 `release_slot()` 释放以便重试。

### 8. 非交易时段跑决策 = 纯烧钱

`paper_store.order` 在 `market_open=False` 时一律拒单 → 半夜开 app 跑 12 个 agent = **16 次 v4-pro 全部产出后被拒**，一笔不成。
**已修**：`run_all(require_open=True)`。非交易时段**仍补判条件单**（补的是历史触发，与当前时段无关），只跳过决策。

### 9. 每个 agent 必须用自己的档位/费率块

`blocks` 曾由 `_agent_boot` 算**一次**传给所有 agent，而 `_tier_block()` 读的是 **active 画像 + 用户真实持仓** → **50 万的中型 agent 拿到用户 7000 块的微型档玩法**，多档位实验完全失效。
**已修**：`app._agent_blocks(ag, cash, total, n_pos)`——**档位跟这个账户的钱走**，**费率跟券商走**。

## 三、会崩的

### 10. `_screen_rows` 有三条互斥分支，测一条 ≠ 另两条活着

```
① focus 且池≤_PA_RANK_MAX(200) → 形态排序，**不调 _balanced_pick**
② focus 但池>200              → 均衡采样，调
③ focus='' 全市场             → 市值预筛 + 均衡采样，调  ← **agent 默认走这条**
```

`_balanced_pick` 曾被一次盲切片（`s[:idx(_pa_score)] + new + s[idx(_screen_rows):]`，它正好夹在两者之间）**整个删掉**，而当时只测了分支①，NameError 潜伏到 agent 跑全市场才炸。
**教训**：改 `_screen_rows` 一带的代码，三条分支都要跑（`tests/test_screen_branches.py` 已固化）。

### 11. 扩池会引爆手工池永不触发的崩溃

手工龙头池数据干净，全市场必踩：

| 位置 | 症状 |
|---|---|
| `ds.tencent_quote` | 全池 4989 只拼成 44KB URL → **HTTP 414**（实测 800 只可过、2000 只失败）→ 已 `QUOTE_CHUNK=400` 分批 |
| `ds._annualized_vol` | 收盘价含 0 → `math.log` **math domain error**，穿透 `executor.map` **打崩整个选股** |
| `ds.sina_metrics` | `closes[-21]==0` → `ZeroDivisionError`；`float(x['trade'])` 在 try 块外 → 空字段 `ValueError` 穿透 |

兜底见 `app._safe_metrics`。

### 12. 局部 import 会让「模块级是否已导入」的检查误判

`current_slot()` 里写过 `from zoneinfo import ZoneInfo`（局部），导致给 `agent_loop` 加模块级 `datetime` 导入时被跳过 → 运行时 `NameError`（**只在挂单路径触发，测试没覆盖**）。
**教训**：统一走模块级导入，别在函数里 import。

### 13. DeepSeek 是推理模型，`max_tokens` 覆盖「思考+正文」

太小会**思考耗尽、正文返回空**（`finish_reason=length`）。
现设：单决策 **8000** / **多空各 8000** / **裁判 12000**。daily=8000 / position=5000 / screen=9000 / market=6000。**别调小**。

**2026-07-16 二次踩中**（补 K 线结构后提示词 8.9k→11.6k 字符）：辩论档 `ok=False`。
实测定位（逐个量，不猜）：

| 调用 | max_tokens | completion | reasoning | 结果 |
|---|---|---|---|---|
| 空头 | 4000 | 2246 | 2080 | 宽裕 |
| **多头** | **4000** | **3578** | 3480 | **= 预算 89%，掷硬币** |
| 多头 | 16000 | 3823 | 3700 | 模型自己收敛在 ~3800 |
| 裁判 | 12000 | 342 | 281 | 宽裕 |

三条教训：

1. **预算要按「逆境下的那一方」定**。空头市里**多头最费思考**（论证「为什么该买」难，
   reasoning 3480；空头论证「别买」轻松，2080）。看空头够用就以为够，是错的。
   → 多空双方**都**提到 8000。
2. **`max_tokens` 是上限不是配额**（按实际 completion 计费）→ 4000→8000 正常情况**不多花钱**，
   只是把掷硬币换成 2.1 倍余量。**没理由抠这个数**。
3. **single 档跑通 ≠ debate 档跑通**（本次 single 全过、debate 全炸）。
   **数据面每次扩容都要重测 debate**——它是 token 预算的最短板。

**单边失败必须炸掉整个辩论，不许降级成一面之词。** 别把 `side()` 的异常 try/except
吞成 `""`：裁判只听一边仍会产出**看着合理**的结论，而没人发现多头没上场——token 耗尽
被伪装成市场判断，且**在跌势里系统性偏空**（多头恰是逆境下最易耗尽的）。属本文件第一类坑。

## 四、环境与数据源

### 14. 东财按端点封 IP

`clist`（批量出数）**封死**——带/不带代理、走/不走 `em_get()` 均 `RemoteDisconnected`。
`slist`（逐股）放行 0.2s。故板块归属只能逐股回填 ~100min。**别再试 clist**。

**封锁范围比原先记的大**（2026-07-16 实测）：不止个股 `clist`，**行业板块 `clist`
(`fs=m:90+t:2`) 同样被封** → `ds.market_breadth()` 的 `advancers`/`decliners`/
`top_industries` **恒为 None/空**，只有涨停/跌停（走 push2ex）还活着。
它**静默降级不报错**，调用方看到的就是「今天没有涨跌家数」。
板块强弱改用 `universe_store.sector_ranking()`（本地库，新浪快照聚合）。

### 14b. 新浪 K 线对未知/退市代码返回 `null` 而非空数组

`json.loads("null")` → `None` → `for x in arr` 抛 **`TypeError`**，而 except 只捕
`OSError/ValueError` → **穿透调用方**。全市场池必踩（同 #11 一类）。
已加 `isinstance(arr, list)` 兜底。**指数用 `index_kline()`，前缀硬编码**——
`market_prefix('000001')` 判 `sz`，而上证在 `sh`。

### 15. 时段判定一律用 `Asia/Shanghai`

`app._market_open()` 曾用 `datetime.now()`（本地），本机恰是 CST 故未暴露——**机器不在北京时区（出国）就会整个交易时段判错**。前端 `_cnTradingNow` 早就用 `Asia/Shanghai`。

### 16. 北交所号段 = 8xxxxx / 4xxxxx / **92xxxx**

`market_prefix()` 里 **`92` 必须先于 `9` 判断**——9 开头的另一支是沪B（900xxx，仍属上海）。
曾有 bug：920xxx 判成 `sh`、4xxxxx 判成 `sz` → 北交所股票**行情/指标全取不到**（加进自选股一片空白）。

### 17. IC 天然滞后 20 个交易日

今日因子值要等 20 天后才知道未来 20 日收益 → **最新可算的 IC 永远是 `today−20`**。
`is_stale()` 必须扣掉这段结构性滞后（≈30 自然日），否则永远判过期、每次启动白跑 14 秒。
**「落后一个月」是正常的，不是数据陈旧。** 代价：方向响应有约一个月延迟。

### 18. 其他

- **端口 5000 与 macOS AirPlay：用 `127.0.0.1` 别用 `localhost`**（2026-07-16 查清）。
  AirPlay(ControlCenter) 监听 `*:5000` 的 v4+v6，Flask 只绑 `127.0.0.1:5000`(仅 v4)
  —— **两者可以共存，不必关 AirPlay、也不必换 5001**。但 `localhost` 优先解析到
  `::1`(v6) → 落进 AirPlay 拿 `403 Server: AirTunes`。故浏览器/curl 一律用
  **`http://127.0.0.1:5000`**。
  ⚠️ **别用 `curl -s URL >/dev/null && echo running` 判断 app 活着**：curl 连上就退 0，
  **403 也算成功** → AirPlay 的 403 会被误判成「app 在跑」（本会话踩过：据此得出
  「app running(旧代码)」，实际 app 根本没启动）。要判活，**看响应体或 `-i` 看状态码**。
- **涉及用户数据的测试必须用临时副本**（`portfolio.json` / `data/*.db`）。
- **AI 接口 30~90s**：`curl --max-time 200`；有代理时 `--noproxy '*'`（python 要 `os.environ.pop` 掉 `*_proxy`）。
- **按日累积的表一律要有 `purge()`**：`sector_daily` 曾无清理 → 977 板块 × 245 日 = **24 万行/年 ≈ 82MB**，10 年 820MB。SQLite `DELETE` 不回收文件空间（页复用），稳态≈1年峰值。
- **`risk_pref` 曾是死字段**：存了、API 能改、前端能选，但 `llm.py` **0 处** → 用户选「稳健/激进」AI 完全看不到。已译成具体行为指令注入（`profile_store.RISK_GUIDE`）。
